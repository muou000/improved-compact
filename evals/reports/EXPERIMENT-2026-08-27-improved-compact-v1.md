# improved-compact 候选策略对照实验 v1

## 决策

候选在当前开发集上取得了明确的任务保真改善，可以进入影子运行或小比例 canary，但**不能据此自动晋级为稳定版本**。它修复了原生工具裁剪稳定丢失中段事实的问题，并显著改善精确路径、命令和标识符保留；代价是 estimated token 节省下降。当前 4 个案例参与过策略设计，没有未见 holdout，也没有真实编码任务的外部状态验证。

## 问题、假设与门槛

基线的首要已知失败是默认 `8192/4096/1024` 工具结果裁剪在摘要前删除中部 `hidden_nonce`，真实模型为 `0/5` 恢复；精确命令和文件路径也存在波动。候选假设是：

1. 在硬摘要阈值前增加确定性的软裁剪层，并从被删中段恢复高信号完整行，可修复中段事实丢失；
2. 对精确赋值采用 last-write-wins，并给摘要增加有界 verbatim 通道，可提高后续任务可用性；
3. 对已有 checkpoint 使用结构化字符上限，可在不增加默认 LLM 重试次数的前提下控制连续压缩漂移。

主要质量指标是压缩后结构化任务成功率。不得退化的指标包括压缩成功率、摘要调用成功率、session log 重放、立即 no-op、工具调用/结果配对、八段摘要调用契约和纠正后的当前值。token 节省、调用 token 与延迟作为共同约束单独报告，不用单一质量分掩盖成本。

## 候选改动

- 窗口 60% 进入模型无关的工具结果软裁剪，80% 才进入原生摘要事务；
- 保留 3072 字符头部、1024 字符尾部，并用最多 2048 字符保存中段目标、约束、纠正、错误、路径、命令和赋值行；
- `key=value` 同键只保留最新写入，疑似凭据行不复制到 verbatim 附录；
- 最近一条直接用户消息只在其完整尾部不超过硬阈值 50% 时原文保留，否则由 checkpoint 锚点承接；
- LLM 输出缺少、重复或乱序原生八段结构时拒绝落盘；已有 checkpoint 的连续摘要限定为 1800 Unicode code points，并按完整章节/完整行缩减；
- 继续复用上游 `compaction/prune`、`compaction/summary`、工具配对、事务、重放和溢出恢复，不写插件私有 session event。

## 数据与环境

- 上游 DSH：`b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`，运行时工作区干净。
- 数据集：`dsh-native-compaction-baseline-v1`，4 个合成案例，22 个字面锚点、10 个 keyless 后续检查；SHA-256 `41376db5d50cf5fc6750427568736c7272128940f154fdbbc79cb381801cbfcd`。
- scorer 未变：SHA-256 `fe5f056b987fa0403d0cf713a00e6a7e81c2b1a79b84aea45a08e9cd5ebd27fb`。
- runner 增加显式 `--strategy native|candidate` 开关：SHA-256 `1bdf422916a7fdbb932068fbfe088395e3ffd61576a386fec1d614948f900437`。
- 候选构建 `lib/index.js`：SHA-256 `4384cc6b64473f3a22943ef17a3f293e403eca17280ba7c367a5f68c68162256`。
- 环境：Windows x64、Node.js `v22.20.0`；真实模型 `openai/gpt-5.6-luna`，配置窗口 `272000`。
- keyless 候选正式重复 5 次；原生确定性基线已固定为同进程 10 次加独立进程 5 次。真实模型基线与候选各重复 5 次。

## 真实模型结果

5 次重复共执行 20 个案例、25 次压缩摘要和 20 次压缩后问答。两组所有调用都成功，结构门均通过。

| 指标 | 原生基线 | 候选 | 变化 |
| --- | ---: | ---: | ---: |
| 压缩成功 | 20/20 | 20/20 | 持平 |
| 后续任务，micro | 38/50 = 76.00% | 50/50 = 100% | +24.00 pp |
| 后续任务，macro | 75.83% | 100% | +24.17 pp |
| 精确字面锚点，micro | 2/22 = 9.09% | 20/22 = 90.91% | +81.82 pp |

逐案例：

| 案例 | 基线后续任务 | 候选后续任务 | 候选 token 节省 | 观察 |
| --- | ---: | ---: | ---: | --- |
| `continuity-core` | 12/15 | 15/15 | 46.70% | 文件、约束和下一命令均为 5/5 |
| `correction-wins` | 10/10 | 10/10 | 51.85% | 当前 region 与 rollback 均为 5/5；旧 region 被主动移除 |
| `tool-prune-middle-loss` | 5/10 | 10/10 | 57.79% | 中段 nonce 从 0/5 提升到 5/5；工具 pair 仍为 5/5 |
| `repeat-compaction-drift` | 11/15 | 15/15 | 53.13% | 最新 driver、迁移文件和下一命令均为 5/5 |

候选严格锚点少的两项是已失效旧值：`deploy_region=us-east-1` 和 `storage_driver=sqlite`。它们分别被 `eu-west-1` 与 `postgres` 纠正；任务检查要求最新值且全部通过。因此 20/22 是 last-write-wins 的预期结果，不应解释成两项当前事实丢失。

概率模型的 5 个语义 digest 仍各不相同，但候选每次的逐案例质量分、压缩次数和结构门结果一致。这里的“不稳定”表示生成文本不同，不表示任务或事务结构失败。

## 风险与未验证项

- 数据集是开发集，不是未见 holdout；本结果证明已知失败被修复，但不能证明泛化或统计显著性。
- 尚未执行真实编码任务的外部状态验证，例如压缩后继续修改文件并重新运行项目测试。
- 尚未请求接近 272k 实际窗口的上下文，因此不覆盖真实临界窗口吞吐、截断和 overflow 恢复。
- 尚未覆盖图片、多个并行工具调用、跨语言长文本、权限变化、摘要超时、损坏 session log 和安全红队样本。
- 规则提取只能识别标签、路径、命令和赋值等显式形态；无结构的中段自然语言仍可能被删除。
- estimated token 节省下降 6.71 pp。若部署更关注成本，需在独立集上调节 `signalChars`、verbatim 预算和连续摘要上限，不能用当前开发集反复调参后宣称晋级。

## 建议部署与回滚

先在影子流量记录压缩成功率、下游任务恢复、摘要调用 token/延迟和失败样本，再以小比例 canary 启用。停止条件至少包括压缩/摘要成功率下降、工具 pair 破坏、当前纠正值丢失、token 或 P95 超出部署预算。回滚点是移除 `improved-compact` 插件，使基础 profile 恢复 `@deepseek-ai/dsh-compaction-basic` 与默认 `tool-result-pruner`；候选只写上游标准事件，已有 session log 无需迁移。

完整逐次 JSON 位于被忽略的 `evals/.local/candidate-keyless-final.json` 与 `evals/.local/candidate-model-final.json`，不包含凭据。
